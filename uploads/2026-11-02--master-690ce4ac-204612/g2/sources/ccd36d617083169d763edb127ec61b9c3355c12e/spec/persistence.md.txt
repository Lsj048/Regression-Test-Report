# 持久事实与故障恢复

本文件是规范性文件。适用范围、术语及变更规则见[规范入口](README.md)。

<a id="data-01"></a>

## DATA-01 两个核心事实源

`message.sqlite` 保存不可变消息事实及其可折叠的追加、范围替换、内容追加；`event_log.sqlite` 保存输入、绑定、运行状态、模型终局、工具、策略、服务、子智能体及交互事实。轨迹、评测和界面状态由这些事实派生，不另建权威副本。扩展可以拥有有命名空间、版本和来源的领域存储，但不得替代核心事实或绕过授权、删除与导出语义。

<a id="data-02"></a>

## DATA-02 跨库提交可修复

消息操作必须先在事件库保存完整且有顺序的写入意图，再幂等写消息库，最后完成待办并补齐审计。任何阶段崩溃，重启必须按写入序号恢复，既不漏写也不重复，不按时间戳猜顺序。两个数据库通过可恢复协议达成最终一致，不能假定存在跨文件原子事务。异步消息使用稳定来源标识去重，并走同一提交路径。

<a id="data-03"></a>

## DATA-03 事件保留足够事实，不复制全部现场

一次有提案的策略调用保存一条包含提案及最终决议的 `policy.proposed`；无提案不写空决策，异常写失败事件。私有状态不复制进事件正文，公开边界按 [POL-05](policies.md#pol-05) 约定，展示派生数据遵守 [DATA-06](#data-06)，不能以公开发布为由重复保存业务状态；服务调用单独记录。模型成功、失败或失去进程所有者分别保存终局事实；流式片段只用于易失展示，不参与恢复或历史计数。不属于轮次的会话与宿主事件保留明确作用域，不伪造轮次。

<a id="data-04"></a>

## DATA-04 派发是副作用恢复边界

| 恢复时的耐久事实 | 允许行为 |
|---|---|
| 动作已计划，尚无派发事实 | 重新校验当前有效作用域、约束与授权后，可以续接。 |
| 已有 `tool.dispatch.started`，缺少最终结果 | 不自动重执行；生成明确的中断结果，标明执行结果未知，并关联实际派发参数。 |
| 已有最终工具结果，消息尚未提交 | 复用结果并幂等补齐消息，不重新调用工具。 |
| 模型在途且失去进程所有者 | 记录中断；不把残留流式显示当完成，不猜测或执行未确认的工具调用。 |
| 已耐久暂停等待审批 | 恢复原请求与轮次；不能当普通崩溃直接丢弃，也不能当已经授权。 |

“失去进程所有者”必须有归属与存活性证据，不能从当前宿主的内存中查不到执行器推导。操作性归属记录不代替轮次、消息或交互事实。旧数据缺少归属证明时保留事实并报告明确诊断；只有确认旧执行器已停止后的显式迁移才可接管，不能静默把旧运行判为崩溃。

<a id="data-05"></a>

## DATA-05 存储完整性是运行前提

正式装配必须使用明确的耐久存储；内存存储只能显式用于测试或临时调用。不可兼容的存储格式必须明确拒绝或显式迁移，不能清空重建或静默降级。事件外置正文属于事件库的物理组成，备份恢复须一起处理；引用、大小或摘要损坏必须报存储错误，不能返回残缺成功。业务失败、用户中止和宿主系统故障须能区分。

<a id="data-06"></a>

## DATA-06 数据唯一归属，展示与交互复用事实

系统应尽可能只保存一份同一业务事实；每类事实必须有明确所有者和唯一权威写入路径。工具、策略、宿主和界面复用该来源，不得各自维护需要同步的业务副本。该要求适用于整个系统，不仅限于核心数据库；存进同一数据库或改名为事件、公开状态、缓存，也不能成为重复保存的理由。

同一业务对象可以保留多个有明确身份的历史版本，用于并发校验、执行恢复和审计；各版本仍由同一所有者管理。禁止的是同一版本为后端执行与前端展示分别保存需要同步的业务副本，不是禁止版本管理。

能从已有事实确定生成的字段筛选、显示文案、进度统计和界面布局，应在读取或传输时派生，不得仅为前端展示、交互或入口差异持久保存一份业务数据或完整展示结果。公开与私有区分的是访问契约，不要求两份存储。通用呈现和专用呈现必须使用同一来源版本；重复读取、刷新或更换界面不得要求领域重新提交状态或写展示事件。

传输数据、浏览器内存、未提交的编辑草稿和流式显示可以有临时副本，但不代表已提交的业务结果。若因有证据的性能或恢复需要保留持久派生数据，必须明确来源、版本、失效与重建方式，不能独立接受业务写入；清除后能由事实恢复。仅称其为缓存、审计或恢复材料不足以证明必要性。

用户实际收到并据此作答的交互请求、回答、授权对象与版本、取消及执行结果属于必须保留的事实。已有不可变记录可完整表达时优先引用其标识和版本；原内容可能改变且无法从已有记录恢复时，可以保存保证回答有效性、审计和恢复所必需的最小不可变快照。不能把旧请求改读成当前内容，也不能只保存无法还原内容的摘要；同时不能以交互记录为名再维护一份可变业务状态或整套界面结果。

已有的消息写入意图、执行检查点及历史记录仍须满足各自的提交与恢复要求。收敛重复数据不得删除仍有恢复或审计意义的唯一记录、改变授权范围，或把内部状态直接暴露给界面；格式变化遵守 [COMP-02](compatibility.md#comp-02)。
