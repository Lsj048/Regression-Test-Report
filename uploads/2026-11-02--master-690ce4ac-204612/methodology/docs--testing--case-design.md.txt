# Case 设计准则

本文统一维护题面、覆盖、断言和稳定性要求。选测试层看[测试分层选择](test-selection.md)，落代码看[新增 SOP](new-playwright-case-sop.md)，已经失败的样本看[归因指南](failure-attribution.md)。产品契约仍以 [spec](../../spec/README.md) 为准。

## 1. 先查真实能力，再写题目

先读对应的 `config/modes/<mode>/mode.yaml`、Tool 的参数 Schema/权限/执行/结果渲染、Policy 的触发条件与 Host 绑定。工具名称不是行为说明，不能猜参数、猜结果结构或猜它会自动完成下一步。Mode、组件或生产投影变化后要重新核对。

一个 Case 验证一个清楚的核心机制，只组合完成它所必需的能力。live 验证真实模型从自然任务选路并消费结果；deterministic 用受控模型响应制造错误、取消、恢复等边界，仍执行真实 Host、Tool、Policy、SQLite 和网页。不要把普通工作流改成脚本响应后声称证明了真实模型能力。

写代码前，先用几句话回答：

| 要写清的内容 | 要回答的问题 |
|---|---|
| 用户目标及完整题面 | 用户实际要完成什么？每轮分别交代了什么要求？ |
| 最小夹具 | 哪些文件、数据或受控服务是完成任务必需的？ |
| 独立业务真值 | 不看模型怎么回答，如何知道结果对不对？ |
| 必经机制 | 没有发生什么行为就一定不能通过？ |
| 允许变化 | 哪些读取、复核、表达或合法恢复可以不同？ |
| 硬边界 | 权限、身份、因果、唯一副作用、持久化、刷新须满足什么？ |
| 预算与不覆盖范围 | 每阶段最多多久，依据是什么；本例不证明哪些能力？ |

不要先运行一次，再把该模型的轨迹照抄成标准答案。

## 2. 题面和断言必须说同一件事

所有用户操作从 Web UI 发起。题面只说用户可见目标、材料和限制，不塞 Tool/Policy 名称、内部事件编号、隐藏调用顺序或测试暗语。可以准备夹具、受控服务和声明过的窗口参数，但不能把后台观察结果伪装成用户输入。动态标识只有在页面实际显示且由 Driver 读取时，才能用于用户的后续任务。

**业务正确性优先于无关的表达形式，但唯一结果仍必须精确。**

| 任务 | 应严格检查 | 不应额外固定 |
|---|---|---|
| 计算 11×11 | 结果为 121 | 没有约定的排版 |
| 写入指定文件和固定内容 | 路径、字节、末尾换行及写入权限 | 没有业务依据的模型轮数 |
| 按原值创建调度 | 题面明确要求原样使用的表达式和生命周期 | 用户未要求的解释文字 |
| 搜索并报告联系人 | 真实搜索、正确来源/值、结果被后续模型消费 | 恰好一次只读调用、唯一措辞 |
| 验证网络查询机制 | 真实联网、返回结果及真实消费 | 非目标的易变外部数值；若用户目标就是数值正确则不能豁免 |

断言要求逐字、固定字段或固定格式时，对应那一轮题面必须明确同等要求。最终回答的格式不能倒用于中间确认。没有业务必要的行数、连字符、标点或 Markdown，不要为了让解析器方便而强塞进题面。

### 每条强制断言都要有必要性依据

**题面与断言严格一致只是第一步，限制写进题面并不能证明它合理。** 每条会导致 Case 失败的硬要求，还须能回答：删除这条检查，会放过哪种错误的业务结果、核心机制漏测，或权限、因果、持久化等契约违约？依据应来自独立业务真值、真实产品契约或本例明确验证的机制，不能来自某次模型的固定走法。

若说不出具体错误，只是方便解析、固定调用次数、参数写法或中间路径，就不应设为必须项。即使先把限制加进题面，再让断言与之一致，也仍属于设计问题。应一起调整题面和断言，而不是要求模型配合无关限制。不得借此删除必要机制、允许猜答案，或把真实产品错误当作表达差异。

| 本例目标 | 合法变化，应允许 | 必须拒绝的反例 |
|---|---|---|
| 监听收到消息后主动停止 | 设置保护性期限，但真实消息已被消费，停止操作在到期前关闭同一条活跃连接 | 连接先自行到期，随后补一个停止调用；没消费消息、停止错任务或留下连接 |
| JavaScript 读取文件、计算并交付结果 | 使用真实输入计算；不同合法调用分步写入、回读并修正目标文件，最终文件与报告正确 | 硬编码结果、最终错值、改坏源文件、越权写入；框架重复派发同一个调用 |
| 压缩后保留明确交接事实 | 正确字段放在句中，或使用「」、『』等正常引号 | 姓名错误、版本号截断、字段冲突；未发生真实替换，或后续请求没消费摘要 |
| 固定数据计算或指定文件交付 | 解释文字和合理复核步骤可变，独立真值仍精确 | 11×11 不等于 121；指定路径或明确约定的文件字节错误 |
| 一次性通知、审批拒绝或故障恢复 | 允许只读查询及声明范围内的合法恢复，不固定无关模型轮数 | 通知重复发送、拒绝后仍执行、没有注入/恢复目标故障却报通过 |

“同一调用只能派发一次”是执行不变量；“整个任务只能调用一次写入”需要另外的业务依据。文件夹具没有中间版本消费者时，不自动增加“一次写入、禁止中间版本”的目标。若业务确实要求付款一次、只发一条通知或只发布完整文件，则必须保留对应副作用检查，并说明实际消费者及风险。

确定性 Case 的固定次数可能正是在验证重试上限、断点恢复或禁止重放，不能照搬 live 的判断删掉。检查的是次数与本例机制有没有关系，而不是见到 `length === 1` 就放宽。页面卡片数量与真实调用记录一致、每个 callId 的唯一派发、身份和哈希匹配，也属于事实一致性检查。

## 3. 机制、业务和展示都要闭合

正向任务要证明机制实际运行、成功结果有正确来源且被目标决策消费。拒绝/取消/故障任务要证明预期终态及禁止的副作用为零。仅出现 Tool 名、最终答案碰巧正确或 HTTP 200 都不够。

观察链按实际机制选择：页面输入 → 模型决定 → 权限/调度 → 原始结果 → Policy 投影 → 耐久消息 → 后续模型实际消费 → 文件/服务真值 → 当前页面与刷新。具体关联字段由[技术方案](web-regression.md)维护。

- 允许合理重复读取、搜索、状态查询和无害表达变化；同一调用被框架重复派发、重复通知仍失败。只有业务本身需要一次性副作用时，才增加“一次写入”等要求，不能为固定审计次数而添加。
- 参数校验拒绝后重试可能合法，但要证明拒绝时零执行、错误反馈被消费以及最终副作用满足要求。不能简单过滤所有失败调用。
- 写入须按实际工具语义逐次核对。不同合法调用对目标文件的分步写入或修正，不等于同一调用重复执行；最终文件正确也不能豁免越权写入、源文件损坏或业务禁止的重复副作用。
- 同批 Write→Read 是否合法，要看真实动作顺序和调度组；不能虚构同批中间模型已经消费结果。跨轮决策则必须核对实际请求。
- 原始结果与最终模型正文可能经 Policy 合法变换。按选中效果、调用身份、来源和完整正文核验，不一律要求两者相同，也不无证据允许不同。
- 耐久原文按原文核对，页面按真实 Markdown/GFM 渲染结果核对，刷新完整一致；只找到一个正确 marker 不能掩盖冲突、截断或错误详情。
- 压缩必须证明实际替换、持久化、净缩减和后续消费；摘要拒绝后从原历史答对不算压缩通过。完整消息组超预算拒绝压缩是保真与可用性的取舍，不是删除持久化历史，见[压缩说明](../bugfix/compaction-summary-retry-budget.md)。

非目标副模型允许的失败开放必须在判定范围中预先说清，并保留完整来源与诊断；不能临时把目标复核改为可选。激活、授权、真实 I/O、状态损坏和证据缺失不属于模型质量豁免。解析复用当次冻结版本的真实契约，不能用新解析器追认旧成绩。

## 4. 给断言加能说明问题的正反例

优先测业务判定函数和共享审计的实际风险，不为每个常量写同构测试。

- 正例：用户目标、机制和真值都对，但合法重复只读、Markdown 或合理步骤变化，应通过。
- 反例：答案正确但机制没发生、业务值错误/冲突、结果没被消费、来源错绑或重复副作用，应按本例目标拒绝。
- 确定性故障反例：没有注入故障却直接成功、没有发生规定恢复、替身收到未知请求，都应拒绝。

新增允许路径时同时说明为何符合真实实现，不能根据某一次模型输出添加特例。只对需要的语义做判断，避免为一个小任务维护通用自然语言解释器。

## 5. 什么叫稳定，什么叫全量通过

下表是取样标准的统一入口；执行命令在 SOP 和运行手册。

| 场景 | 同一冻结版本所需样本 | 能登记的结论 |
|---|---|---|
| 单次探针 | 1 次 | 调试观察，不能叫稳定 |
| live 单项新增/实质修订 | 5/5 有效样本 | 该 Case 单项稳定 |
| deterministic 开发批次 | 3/3 有效样本 | 确定性单项开发资格，不是五样本全量资格 |
| 完整联合/每周门禁 | 两路每 Case 5/5，并通过正式证据校验 | 该冻结集合的正式结论 |
| 自动、手动 Compaction 两个专项 | 各 6/6 | 保留更严要求；第六次不能抵消前五次失败 |

每场只用一个冻结源码/编译产物、模型身份和配置、题面与断言版本，单 worker、零 Playwright retry；不跳过失败、不跨场拼 PASS。模型或服务未报告 revision 时如实写未报告。改变题面、断言、目标实现或配置后，旧成绩作为历史保留，新候选重新取样。

每批最多五项、最多三场完整实验。每次修改先有归因和有依据的不同处置；某项达标后退出后续修订批次。三场仍无法收口则标为待人工 review/bad case，保留代码与失败；不得静默从要求全量的集合中移除。先前模型问题按既定范围只登记，不能补抽刷绿。

外部补样资格单独按[归因指南](failure-attribution.md#5-网络429长尾与补样)和冻结分类器核验。原失败与替补映射必须保存；HTTP200 空响应、非法参数、摘要污染或业务失败不补样。正式结果取校验器，分析意见不能改写原判分。
