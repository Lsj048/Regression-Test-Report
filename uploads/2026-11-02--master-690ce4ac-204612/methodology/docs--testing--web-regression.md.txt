# Web UI 回归测试技术方案

本文维护 Contract、Driver、隔离环境和证据审计的实现约束。当前资格与失败归因统一见 [Case 台账](../../test/e2e/cases/README.md)，不在本文累计实验过程。

## 1. 执行结构

文件之间的关系和职责先看[新增 SOP 的运行流程图](new-playwright-case-sop.md#2-这些文件怎样把一个-case-跑起来)。其中：`evaluation-cases.ts` 登记要求并选择集合，`case-drivers.ts` 找到对应操作代码，`web-regression.spec.ts` 逐样本准备/清理环境并调用 Driver，Driver 负责网页动作和调用审计。

实际业务链是 Web UI → Host → Kernel → Policy → Tool / 子 Agent。Driver 结合页面、只读 HTTP、SQLite 和业务文件检查结果。Playwright 使用单 worker 按定义顺序执行；一项失败不会跳过后续项。新增 Case 复用共用环境，不在总 spec 中复制服务启动代码，也不把页面步骤抽象成另一套声明式测试语言。

## 2. 核心模块

| 文件 | 职责 |
|---|---|
| `test/e2e/evaluation-cases.ts` | 定义 Case 标识、Mode、模型通路、耗时、必经 Tool/Policy 概要和产物名称；profile 只选择当前 Mode 兼容项，并在执行前拒绝缺失或禁用的组件 |
| `test/e2e/case-driver.ts` | 定义 Driver 与隔离环境之间的最小接口 |
| `test/e2e/case-drivers.ts` | 保证每个已注册 Case 有且只有一个 Driver |
| `test/e2e/*-scenario.ts` 或共用场景文件 | 定义题面、材料内容、预期值和可复用的 Case 声明；不操作浏览器 |
| `test/e2e/cases/*.ts` | `prepareWorkspace` 写材料，`run` 输入/点击/等待，调用 audit 后核对页面及刷新并挂附件 |
| `test/e2e/audits/*.ts` | 只读后台记录和业务文件，检查真实执行、来源、后续使用和结果正确性 |
| `test/e2e/web-regression.spec.ts` | 按样本创建目录/端口，调用 Driver 准备材料，启动模型与 Web 服务，调用 `run`，最后收集现场、停进程及导出轨迹 |
| `test/e2e/http-readiness.ts` | 用共享绝对截止时间约束健康、配置和模型代理启动请求，防止单次 HTTP 请求无限等待 |
| `test/e2e/fixtures/deterministic-model-server.mjs`及按领域拆分的确定性替身 | 为基础自检及已注册故障Case提供受校验的可控模型响应 |
| `test/e2e/fixtures/live-model-proxy.mjs` | 在本机回环端口代理真实 Provider，隔离真实密钥，并过滤请求与响应的逐跳 Header |
| `test/e2e/live-model-config.ts` | 校验真实模型变量、限制不安全地址并生成脱敏配置 |
| `test/e2e/failure-diagnostics.ts` | 在失败清理前读取 SQLite 状态摘要及逐 Turn Policy 私态，并提取代理阶段事件；另保存 `context.rejected` 完整 payload 与逐次 Compaction 摘要候选正文（finishReason、字节数），用于压缩类失败的结构归因；私态可能含固定任务和产物内容 |
| `test/e2e/managed-process.ts` | 统一启动和停止评测子进程，记录每个进程的清理结果并拒绝强制结束或停止失败 |
| `test/e2e/sqlite-audit.ts` | 提供共享 SQLite 读取、完整性检查、主模型请求闭环和基础设施冒烟审计 |
| `test/e2e/audits/*.ts` | 核对各真实模型 Case 的 Tool、Policy、消息和领域存储硬事实 |
| `test/e2e/playwright.config.ts` | 配置浏览器、超时、截图、trace 和 JUnit 输出 |

Case Contract 说明“本 Case 必须证明什么”的稳定概要，Driver 说明“如何从页面完成任务并取得证据”，专属审计执行参数、顺序和业务真值等细粒度门槛。同一 Mode 可以有多个小 Case；Case 标识是三者之间的唯一关联键。

确定性Case按领域复用模型替身、Driver工厂和审计，但Contract与Driver逐项显式注册，不因场景常量增加而自动进入执行集合。新增一项时同时增加两处注册和数量/兼容控制；每项仍创建独立环境并执行全部业务断言。共享实现、单项注册与已知缺陷复现分开提交，登记复现不等于取得稳定资格。

注册库存、Mode兼容集合与可执行profile不是同一概念。当前注册的live Contract均可执行，没有Mode或PTC排除；030产品缺陷已修复，当前个别Case未稳定不等于机制仍受该缺陷阻断。兼容检查覆盖 Case ID 与 Mode 身份、必需和可选 Tool、必需 Policy、动态 Tool 注册入口、PTC 嵌套 Tool 以及 Standard PlanMode 装配，防止 Case 在错误 Mode 下静默运行或缺少目标机制。当前数量、旧身份映射和逐项资格由 Case 台账维护。

静态模型 Tool 面必须直接由当前 `mode.yaml` 选中的 Tool 加已启用的子 Agent Tool 派生；统一 Host 会把这些已选定义全部放入模型请求，评测层不得保留旧 Web Host 的手写排除列表。连接型 Tool 的外部适配器是否配置、调用后是否成功属于执行期事实，应由目标 Case 的真实调用、服务事件和结果断言证明，不能通过从预期模型面删除已激活 Tool 来表达。动态 Tool 仍只在其注册事实之后加入该静态面。

`timings.payload` 只包含该 Contract 的 `timingBudgetsMs` 所声明的数值键，记录实测耗时而不是预算值；未声明预算的流程总耗时等诊断指标放在 `sqlite-audit.payload`。最终报告按完整键集合及逐项预算校验，浏览器流程通过不能替代附件契约检查。字段修订只影响新运行，不能离线改写旧附件获取通过。

## 3. 环境启动与清理

`HARNESS-037`：Kernel 收敛保护可能抛错却留下非终态 Turn，Host 追加 `turn.failed` 事件并不能替代失败状态提交。诊断应同时核对事件和耐久 `kind/turnOutcome`；后续 `TURN_ALREADY_ACTIVE/INPUT_NOT_NEXT` 不应当作网络失败补样。本次专项授权后已修复并验证，日常Case工作不因此获得任意Kernel修改权；仍不干预用户报告的旧阻塞会话；详见 [收敛保护说明](../bugfix/drain-nonconvergence-session-block.md)。

确定性恢复必须同时核对当前页面和刷新后的事实：`HARNESS-038`证明数据库完成不等于SSE已送达，不得靠先刷新再断言掩盖当前页面挂起。停止审批也不能用“没有写文件”替代取消语义，`HARNESS-039`旧热路径把停止写成权限拒绝，下一模型会读到错误分类。两项已在专项授权下本地修复，原页面及耐久断言保留，当前资格见Case台账；见[冷审批通知](../bugfix/cold-approval-event-notification.md)及[热审批停止](../bugfix/active-approval-stop-classification.md)。

动作拒绝还须核对公开历史：`HARNESS-040`中真实denied结果因没有执行用tool.call，被Host重建为成功、工具名丢失。既不能伪造派发事实补卡，也不能删除页面拒绝断言；见[拒绝历史投影](../bugfix/action-rejection-history-projection.md)。压缩故障则区分原始不可变消息和当前模型可见面：保留数据库原文不等于后续请求能读到，摘要文本存在也不等于选中并消费。确定性剧本必须分别验证这两层。

远端传输成功也不等于业务执行成功：MCP的`isError:true`须在真实Tool结果中保持失败语义，不能只验证模型最后说了“失败”。`HARNESS-041`的MCP扩展修复见[错误信封说明](../bugfix/mcp-tool-error-envelope.md)。Assistant确定性替身还必须显式处理已激活的记忆提取副模型请求；不能关闭策略或用通用成功响应消除未知请求。

每个顶层 Case 单独执行以下流程：

1. 通过 `mkdtemp` 创建短、随机且隔离的 `lch-e2e-*` 根目录及工作区、状态目录和用户目录；macOS 使用 `/tmp`，其他平台使用系统临时目录，并向 Host 传递工作区的真实绝对路径；
2. 写入该 Case 专用的 `settings.yaml`；
3. 为事件库、消息库和 Policy 自有数据使用独立路径；
4. 分配随机模型端口和随机 Web 端口，并明确拒绝 `8088`；
5. 启动模型替身或真实模型回环代理；
6. 启动当前 Mode 的 Web Host；
7. 在同一个服务启动截止时间内，通过带请求中止信号的 `/api/health` 和 `/api/config` 核对服务、模型、工作区、权限和 Mode；服务只接受连接却不返回响应时必须按预算失败；
8. Playwright 执行 Case；
9. 隔离环境启动成功后若 Case 执行失败，先读取 SQLite 状态摘要及逐 Turn Policy 私态；不另复制完整消息和事件载荷，私态仍可能含任务和产物正文，须脱敏并按内容证据管理；
10. 先停止 Web、再停止模型进程，并对温和退出和强制结束分别设置有界等待；即使某个进程停止失败，也会继续尝试停止其余进程；
11. 待输出流关闭后保存完整日志和失败诊断；诊断会列出每个进程是已停止、温和退出、强制结束还是停止失败；强制结束或停止失败会使本 Case 失败；
12. 删除临时运行状态，并确认 `8088` 监听快照未变化。

Web Host 以该 Case 的临时 `HOME`、`USERPROFILE`、`XDG_CONFIG_HOME`、`XDG_DATA_HOME` 和 `XDG_STATE_HOME` 启动，并显式传入 `--state-dir` 与 `--static-dir`；日常用户配置因目录隔离而不可见。`LONGCAT_STATE_DIR` 与 `--state-dir` 必须指向同一个临时状态目录，使 Web 入口执行前加载的仓库内 Node preload 夹具和 Host 使用同一状态根。固定项目夹具仍属于 Case 工作区，可以被正常读取。该隔离完全由 Playwright 启动 Web 子进程时设置的环境实现，不依赖额外产品开关。

目前环境实现是本地临时目录和进程隔离，Driver 和审计仍直接访问宿主机文件与 SQLite。未来容器化前需要先抽象文件读取、命令执行和数据库证据通道；当前不能直接切换为容器后端。

当前带 Bash 的低权限 `live` Case 只在 macOS 上验证，依赖系统 `sandbox-exec`。Linux 尚无等价沙箱后端，接入跨平台持续集成前必须先补隔离实现或明确使用受信任的专用 macOS 执行器。

PTC嵌套异常按实际拦截层审计：服务授权拒绝没有嵌套执行，Schema拒绝有调用结果但没有派发，实际I/O失败则必须有唯一派发。服务返回完整关联父RunCode、嵌套调用、原始结果和程序真实返回值；嵌套结果不创建独立模型消息。父程序正常返回一个失败报告不代表业务成功。实时和刷新投影分别核对全部卡片及详情；HARNESS-030曾使嵌套失败在刷新后退回运行中，现已修复；不能因此只保留父卡断言。

## 4. `live`：真实模型主链

真实模型调用必须显式提供评测配置；基线参数和运行命令统一见 [运行手册](../../scripts/evaluation/README.md) 第 2、8、9 节。

真实模型通路与确定性通路使用相同的 Harness 和页面实现。真实 Provider 请求先经过本机回环代理，Web 子进程只得到随机临时令牌；日志和产物记录脱敏后的模型名称、Provider 地址和版本标识，不记录真实密钥。代理可以接收合法的分块请求并在读取后重新发送固定长度正文；请求和响应都过滤标准逐跳 Header 以及 `Connection` 动态声明的 Header，响应还会去掉代理解压、重新传输后不能沿用的 `content-encoding` 和 `content-length`。代理另记录请求已接收、上游请求已发出、响应头已到达、首个响应数据块已到达以及流完成、中止或失败的时间点；这些记录不包含请求正文、响应正文或完整请求头。

代理的有界只读取证可将同一responseId的正文/推理SHA-256与落盘结果比对。完整SSE含供应商控制标记时，仅保留`wireTextEvidence`及`verified:false`，用于判断异常文本是否已存在于上游；它不证明零工具调用，不放行摘要，也不授予网络补样资格。截断、未知协议或超过1MiB的响应不输出可验证文本哈希，证据不足仍须保留。

工具参数/缺失结束标记的定位另用`wireDiagnostics`：逐choice/call索引重组参数并保存哈希、JSON合法性、帧数及finish标记；与耐久工具参数比较，不能自动修复参数。`complete`仅表示未超过取证大小上限，不代表模型协议完整。默认不保存原文，专项诊断可显式开启1MiB以内的脱敏原始响应保存；`utf8Lossless=false`或超限时不能声称可逐字回放。底层连接失败保留有界`causeCodes`，区别DNS/证书配置与传输故障；以上字段不改变网络豁免规则。

代理取证与产物归档分别检查。托管子进程的stdout/stderr使用各自的增量UTF-8解码，不能逐字节块直接转字符串，以免日志管道拆开中文字符后破坏JSON正文。即使代理报告完整、无损，复演前仍须核对归档字节哈希；不符就记录缺口，不能靠修改原始证据使其通过。该测试侧修正不改变实际Provider传输、Case业务断言或网络补样资格。

参数由 `test/e2e/live-model-config.ts` 生成测试 Web Host 的临时设置，并写入脱敏评测元数据。Case 可以由 Contract 覆盖上下文窗口或模型输出上限（`modelSettings.contextWindowTokens` / `modelSettings.maxOutputTokens`）。当前自动压缩为 `32768/8192`、手动压缩为 `32768/16384`：Kernel 的 `MODEL_COMPLETION_SERVICE` 会把策略请求的输出预算与会话模型输出上限取 `Math.min` 封顶；以执行 Contract 和运行手册为准，不沿用旧 `61440/24000` 基线。环境身份、`/api/config` 和 SQLite 审计必须看到同一个值。调整任一默认值或 Case 专属值都会形成新的模型基线，不能与旧样本直接合并统计。

安全检查包括：

- 没有 `LCH_EVAL_ALLOW_LIVE=1` 时拒绝执行；
- 远端 Provider 必须使用 HTTPS，本机回环可以使用 HTTP；
- 不允许把 `127.0.0.1:8088` 作为 Provider；
- 不读取用户日常 `settings.yaml` 中的密钥；
- 缺少模型名称、地址、密钥或版本标识时，在打开浏览器前失败。

真实模型可以采用不同的合法轨迹。Driver 只把完成任务必然需要且可以从后台事实核对的机制列为强制证据；其他允许行为可以出现，但只记录，不计该 Case 的覆盖，也不能替代核心组件。强制证据缺少、执行失败或结果真值错误时，本次样本必须失败。

刷新检查不能要求事件总数停在第一次审计的值：`turn.completed` 之后仍可能追加 Host 收尾事件。FIFO 在刷新前后分别执行完整审计，保留输入与 Turn 身份、FIFO 顺序、精确答案、唯一业务执行、工具及消息证据、空队列和空消息 outbox 检查；比较结果时只排除 `eventCount` 的相等要求，仍拒绝计数减少和其他字段变化。最终附件保存刷新后的审计，不用旧快照覆盖新增事件数量。不能只看最后答案正确就跳过第二次完整审计。

Contract、题面和专属审计必须表达同一粒度的用户要求。若审计要求 cron 表达式逐字段、文件内容逐字节或生命周期选择保持原值，题面必须自然地明确“按原值使用，不重新计算或改写”；题面只要求业务效果时，审计不能额外固定调用步骤、模型措辞或无业务依据的表示形式。无论结果是否唯一，目标机制的真实执行和后续模型对其结果的因果消费都不能省略。

题面与断言一致也不自动说明设计合理。例如Notebook单元编辑的真值在文件与编辑结果，不在完成答复的固定标记或行数；此类非核心格式应同时从题面和断言移除。仍核对真实编辑、其他内容不变、权限、结果消费、正常完成、耐久正文及刷新，不把允许自然说明变成仅看最终答案的宽松判断。

结果投影按规范 ACT-05 审计：`tool.raw_result` 是策略前事实，`tool.result` 是投影后的模型正文，两者不必逐字相同。共享审计从同 Session/Turn/Call 的选中 `project_action_result` 提案重建正文，并核对绑定组件版本/校验和、投影顺序及原始结果与提交结果之间的事件边界；canonicalValue、状态、授权、实际派发、持久化和后续消费继续独立检查。无选中提案的正文变化仍失败，不能只凭 Policy 名称放行。

Markdown 源文与页面采用同一渲染语义比较完整内容，只排除代码块语言栏等界面装饰；不能把反引号、强调符号或自然字段名差异判成业务错误。中间转述若没有固定格式约束，应验证正确且无冲突的业务字段与真实投递/消费，不额外要求最终答复的排版。

确定性故障服务应在有限请求上限内持续提供声明的故障，允许受测产品依配置重试。摘要 HTTP500 没有可修复的候选，不能要求其携带 rejectedCandidate；只有收到不合格候选后的语义修复才检查候选和修复提示。故障次数按本次绑定参数限定，零替换、原历史保留及后续召回不因重试变化而放宽。

可读业务夹具中的测试控制细节也可能干扰模型选路。运行中协作者 Case 的旧脚本依赖 `LONGCAT_STATE_DIR/e2e-control`，普通只读预检可把这些细节带入上下文。本轮改用 Driver 在核实 PID、进程组、真实消息投递和父任务等待后才发送完成信号；仍验证释放前进程存活且没有结果、释放后真实输出、模型消费及进程清理。此改动减少夹具依赖，不把后续五轮成功解释为已修复所有历史模型偏离。

“只创建一次”按实际派发及创建事实判断，不直接等同于一次模型调用。允许参数失败后恢复时，先读真实Tool Schema及校验顺序，证明失败未进入权限、派发、服务或实体创建，完整错误已耐久提交并被后续请求消费；再独立审计唯一成功调用的业务链。页面也应保留未执行失败的错误卡片，不能用“成功调用会归并为业务卡片”推断所有同名尝试都不展示。当前页面和刷新都按各次真实结果核对。

当前 Standard 的装配声明位于 `config/modes/standard/mode.yaml`，统一装配根仍是 `src/kernel/host/runtime/mode-runtime.ts`。合并当前 `master` 后，它显式加载 `EnterPlanMode`、`ExitPlanMode` 和 `builtin.plan_mode`；对应实现归属 `src/extensions/planning/`。因此 Standard 冒烟和真实模型 Case 都会看到新的 Plan Tool/上下文，但只有实际进入并完成相应流程的 Case 才能声明 Plan 覆盖。Tool 面、上下文和绑定变化使合并前 Standard 真实模型资格不能直接迁移；旧成绩保留，新树重新冻结复验。未硬编码旧组合且核心业务语义不变的 Case 可以只复验，无须一律重写。

## 5. `deterministic`：基础自检和故障通路

确定性模型替身仍通过真实 OpenAI 兼容 HTTP/SSE 接口与 Harness 通信。当前 `standard.infrastructure-smoke` 返回固定助手文本，用于验证：

- Playwright 能通过页面创建会话并发送消息；
- 模型请求、流式解析、消息提交和页面投影连通；
- 事件和消息写入独立 SQLite；
- 任务完成状态与数据库一致；
- 刷新后会话和结果仍然存在；
- 测试日志和结果摘要能够生成。

它不调用业务 Tool，不证明 Standard 的任务能力，也不计入 G1 覆盖。

当前替身 revision 为 `deterministic-model-server.v5`，只接受基础自检的主模型协议：请求必须使用实际模型、SSE、`auto` 和非空合法 Tool 面；system 角色保持首位，唯一精确自检任务、Standard 的 Plan 入口提示和当前时间上下文各出现一次。检查按全部 user 文本块的业务语义聚合，不固定 Provider 将相邻同角色内容合并成几条消息或几个内容块；时间上下文仍按 Date/Intl 核对时间戳、IANA 时区与本地显示。主 system 内容不做全文固定，自检不证明提示词质量。

Standard 的 `builtin.contract_ledger_reminder` 当前仍唯一出现在同 Turn binding 中，但必须显式 `enabled=false`；审计要求它没有模型服务调用、私有状态和结果投影。替身不再实现 `contract_ledger_extraction` 空账本响应，任何意外副模型请求、未知任务、额外角色或不支持协议都会失败，不使用全文关键词匹配或通用 COMPLETE。该 Policy 的当前实现与解析器位于 `src/extensions/verification/contract-ledger-reminder-policy.ts`；历史启用版本的提取/复核证据只解释其冻结样本，不是当前 Standard smoke 的预期。剧本协议变更继续更新 revision，并另冻结复测，不改已运行样本。

环境启动还会校验 `/api/config.modes`：每个 Mode ID 必须是非空字符串且全局唯一，列表必须包含当前 Case 选择的 Mode 及现有 G1 基线 Mode；不再断言列表恰好只有三项。这样新增由配置目录发现的 Mode 不会让冒烟失败，同时仍能发现当前 Mode 丢失、重复 ID 或基础装配缺失。

故障Case已按Provider、工具、生命周期、收敛保护、压缩、MCP、PTC、硬限制、子任务及进程等待分别注册。替身只控制外部故障或模型输出；专属审计将声明的异常与实际请求、派发、结果、消息和终态逐项关联，其他失败仍由公共审计拒绝。基础smoke没有失败豁免；计划内500、超时及断连不进入网络补样。逐项设计和资格只在Case台账维护，确定性通过不代替真实模型正常任务。

取消类必须区分三件事：用户停止事实已经保存、工具等待已经结算、所属后台资源已经清理。三者不能用一个页面按钮或进程状态替代。等待输出被取消，应保留读取操作的cancelled语义；取消读取不得误杀由其他上下文拥有的独立进程。取消完成后由页面发起下一项独立任务，并复核当前与刷新投影，防止一个工具失败把整个会话占住。

停止状态修复已整合到 Case 分支：耐久中止后，尚在清理的驱动不能把列表／详情重新投影为 running；但执行占用仍保留，新输入须等清理结束再执行。对应集成控制区分中止提交前后、响应头与流式阶段、排队续问和冷恢复。修复说明见[停止清理状态](../bugfix/stop-status-during-transport-cleanup.md)，当前验证边界见 Case 台账；旧全集失败不追改。

## 6. Playwright 页面边界

工具执行结果、问题回答状态和轮次能否停止要分开核对。普通追问工具可以已成功执行，但问题仍未回答，工具卡应显示“等待回答”。按 STA-03，普通追问以等待结果结束原轮次；没有运行中的子任务时，不应显示轮次停止按钮。权限审批则暂停原轮次，仍可停止，不能根据工具名称或“等待回答”样式推断两者相同。

`checkLiveBusinessTools` 只用于审计已确认根、子执行都结束后的页面：逐卡核对状态、参数和结果，并要求轮次停止按钮不存在，普通待答问题也适用。运行中、子任务仍运行、待审批阶段由各 Driver 单独检查，不能调用这个结束态检查代替。Driver 仍以耐久请求、调用和轮次身份确定哪张卡待答，并在刷新后再次核对；Goal 的暂停／取消入口独立检查，不点击它们来凑出预期终态。不能把所有成功工具结果映射为成功样式，也不能取消待答状态、问题身份或刷新检查。

用户可执行动作必须在页面完成，包括：

- 核对隔离环境预设的 Mode、工作区和权限；
- 输入并发送自然语言任务；
- 回答澄清、批准或拒绝操作；
- 观察运行、等待、失败和完成状态；
- 查看 Tool 或子 Agent 投影；
- 刷新并重新打开会话。

Case 不能通过内部 API 代替发送任务、新建会话、澄清或审批等用户动作，也不能在用户输入中要求调用不可见的内部组件。后台接口和 SQLite 只用于准备隔离条件、等待系统状态以及在用户流程之后核对事实。

页面断言根据 Case 需要覆盖运行态控件、权限锁定、追加消息、完成态操作、刷新恢复、控制台异常和非预期 HTTP 错误。稳定控件优先使用 `data-testid`，用户真正看到的状态仍通过可访问性角色和文本核对。

最终回复与工具轮说明应按耐久消息的 `source_event_seq` 关联 `model.completed`，结合是否包含 Tool 调用区分；不能把所有非空 assistant 消息都计成页面最终回复。消息正文与事件正文仍须一致。异步检查点应等待被审计的业务边界提交完成，例如投递后的回复模型完成及同一 Turn 的等待事实；仅看到 Tool 成功结果，不代表后续请求计划已经全部结束。

子 Agent 展示按实际模型步骤中的工具数量核对单次或批量标题，再逐调用核对身份、参数、状态与结果，不要求模型逐个发起可批量的只读操作。跨轮跟进必须区分因果根与直接父轮次：当前 `SubagentRuntime.followup` 保留发送方状态的 `rootTurnId`，将 `parentTurnId` 设为发送轮次，并关联实际调用 ID；输入、续轮和完成通知均按这条链验证，不能把根轮次误写成本次发送轮次。

## 7. 后台事实与硬真值

判定由三层证据组成：

1. 核心组件硬门槛：Contract 记录必经 Tool 和 Policy 概要，专属审计执行具体参数、服务调用、顺序和结果要求；缺少任意核心证据即失败。
2. 可选轨迹记录：允许模型改变调用顺序或增加声明允许的操作，但这些操作不计覆盖，也不能补偿核心证据缺失。
3. 多事实面一致：事件与 SQLite 中的模型和消息原文逐字一致，页面渲染文本在刷新前后逐字一致，工作区或受控服务真值与各层结构化结果一致。

通用审计根据 Case 实际范围检查：

- Session 和 Turn 的状态与页面一致；
- 模型实际可见的 Tool 表面符合所选 Mode；
- 每个必经 Tool 具有完整调用、调度和结果生命周期；
- `tool.scope.bound` 只证明 Turn 的 Tool 作用域已绑定，不等于 Tool 被模型选择或真实执行；零 Tool Case 应核对其根级、无限制形态，并同时以零模型 ToolCall、零 call/dispatch/raw/result 和零页面 Tool 卡证明没有执行；
- 必经 Policy、压缩、消息替换或子 Agent 事件顺序正确；
- `message.sqlite` 中用户、助手和 Tool 消息完整；
- 未消费输入和待写队列在结束时清零；
- 除 Case 明确允许外，没有模型、Tool 实际执行、Policy 机制或状态机失败；非目标副模型输出质量诊断与目标错误分开判定，激活、授权、身份、实际 I/O 和证据缺失始终失败。

每个 Case 还需要至少一个不依赖模型措辞的业务真值，例如文件哈希、固定测试结果、SQLite 字段、受控 MCP 返回、进程退出码或请求记录。模型最终回答只作为页面结果的一部分，不能单独决定通过。

## 8. 跨层证据对齐

本文维护具体证据协议。题面、断言和允许变化见[设计准则](case-design.md)；失败分类、外部补样及排查经验集中在[归因指南](failure-attribution.md)，不在这里另设一套方法。

`mainModelRounds` 按 Session/Turn、planId 和 requestHash 逐请求配对全部规范计划与主模型完成事件，禁止缺失、复用或跨 Turn 绑定。既有正常协议需要定位业务决策轮时，仅剔除已完整证明的输出续写中间轮：length 且无 Tool 的主结果、output_continuation 的 selected continue_turn、同贡献的状态转换与耐久指令、下一 step、匹配 outcomeId 的 selected continuation/output、实际请求 manifest 的唯一 appliedEffectId 和完整 after_messages 内容。其他运行时块可以位于续写块之后；未证实的额外轮不豁免。返回的全部计划/完成仍须取证，businessPlans/businessCompletions 只用于定位，不是新的模型请求事实源。Case 自有的只读重复、批量动作和业务副作用约束仍由专属审计执行。

输出续写的每轮 Assistant 由正常 append 提交，不能把该路径误写成 append_content。历史分叉的 history_seed 消息与当前实际模型来源分别校验。允许合理重复或 batch 不改变逐 callId 的唯一性：每个模型请求、可执行动作、权限、调用、真实结果、耐久消息和后续消费仍须独立关联，trace wrapper 不能重复算作可执行动作。

符号导航及精确修复的完整阅读允许按实际 offset/limit 联合覆盖固定源文件；每片的边界、正文、原始渲染、耐久来源及目标决策请求中的实际消费都独立核对，末换行的空 split 哨兵不作为额外必读内容。导航结果仍须进入实际回答请求；修复前源片必须进入首次编辑请求，不能用事后读取替代。日期任务允许完整证明的输出续写，但每个实际请求的时间效果、绑定、manifest 和全文注入必须闭合，同 Turn 缓存样本不能重采样；最终页面答案须独立为完整合法 JSON，不由评测器拼接片段。

Tool 决策轮可以包含合法的 Assistant 正文，不能以“非空正文只能有最终一次”推定持久消息数。MCP 目录、连接刷新、网页搜索及 PTC 文件交接按实际 model.completed 的 source_event_seq 逐项核对全部 Assistant 内容与 Tool 请求，最终结果仍唯一绑定最后的正常完成；PTC 首轮冻结保留过程消息但只选择该轮最终事件的 JSON 报告。PTC Driver仅在timeline-group直属Assistant中选正式回答，活动内所有非空过程正文按实际模型/耐久来源、ReactMarkdown/GFM完整渲染文本、动态数量及刷新全文独立核验，不能用忽略过程正文代替允许合法正文。用户明示的最终格式、唯一搜索交换和其他 Case 专属语义不因此放宽。

后台或续聊任务的 completed 可以先于当前页面正文到达，也可能只是合法过程报告。Driver 应在原业务绝对 deadline 内同时等待后台完成和当前最后业务报告，不能读到上一报告便退出，也不能将完整预算重启为额外等待窗口。等待时继续拒绝非预期问题和未知终态；最后业务真值、完整耐久来源、专属审计及刷新一致性不变。合法变更后只读复核可在同批执行：以实际 ordinal、动作顺序、独占组及变更结果先于读取开始证明，不虚构同批内不存在的中间模型消费；跨轮依赖仍核对完整结果实际消费。

直接 Tool 的 actionPlanId 和 ordinal 必须把原始、耐久结果分别绑定真实调用；仅 raw 与 durable 相等不证明身份正确，ordinal 还要等于实际 canonical actions 数组槽位。已完成协作者续聊的成功只读工具没有实际结果投影效果时，正文须精确匹配标准输出，不用 prefix 判断放行无证据尾文；Read 的 canonical 切片及其标准渲染独立核对。

PTC 直接 RunCode 必须有唯一 dispatch；现有核心服务 invoke 不传 batch 的 beforeExecute hook，嵌套工具以 service -> call -> permission -> raw/result -> service completion 闭环。嵌套若带 dispatch，则身份、顺序、唯一性同样严格核验，不得孤立。父 service actionId、嵌套 parentCallId/ordinal 和权限资源都与真实执行相符，嵌套结果不应进入独立模型 Tool 消息。生成程序的双输入重放使用真实 envelope 格式，从实际结果选定同一返回或日志通道及结构位置，完整源或统计必须随数据变化，不能递归搜到任意常量就通过。实时与刷新后的工具卡都检查成功态和精确详情，不因调用已在 SQLite 成功而跳过冷页面投影。

PTC 任务计数以实际完整获准 catalog/schema 和录制服务交换复演现有 RunCode.execute，只提供响应、不调用 Host I/O。实际输出与 0/1/3 输入复演在同一通道及结构位置返回对应计数或完整任务数组；支持任意 JSON 键，自然文本按完整数字归一化模板及数字位置绑定。固定值、跨位置常量及只判断空/非空不能通过。非核心动态元数据不要求复演全文相等，原始/canonical/耐久/请求全文及调用身份仍严格；审计副本 timeout 最多一秒且保留原更短值，不改业务预算。最终明确报告正确且无冲突的任务总数，允许解释、Markdown和一致重复确认，不要求固定末行。

计数合成任务的合法编号、状态和时间不与条数共线，避免最大编号或仅 pending 数冒充任务总数。原空清单复演仍完整逐序消费录制交换；单条和多条反事实允许数据驱动的合法只读复核增减或改序，响应来自已核验录制交换或绑定 catalog。未知工具、修改操作、变参及无效协议即使被生成程序 catch 也须最终拒绝，不固定反事实执行脚本。

Assistant 记忆按每个真实无 Tool 动作的主模型 outcome 核验捕获交换及存储来源，不按每个用户 Turn 固定一次。save 初请求及首次捕获完成前不能有预存记忆，后续请求可消费本 Turn 已保存的记忆；最终仍唯一 active 记忆和唯一 ADD。跨会话召回排除全部 save 用户及 Assistant 正文，召回本 Turn 已闭合的 Assistant 历史可以合法存在，不能单凭同文误判泄漏，也不能接受无耐久来源的伪历史。

save 后继记忆须由真实新增事务证明，而非任意完成的捕获或原始 ADD 建议：现有领域存储以同一 created_at 写 ADD history 和 capture，按 timestamp、namespace、Session、Turn 唯一关联，再绑定已闭合 outcome/service 及完成 seq 先于模型请求。歧义关联仍失败；不新建存储事实、不复制 Policy 解析与仲裁。零提案diagnostics不一定持久化，不能把它当作存在的成功事实；HARNESS-028已按无提案不写空决策的设计撤销原定性，不再作为待修缺陷。

冷会话展示的目标契约是通过 Repository 读取含嵌套调用的 Turn 中真实嵌套结果，保留原事件身份及终态；普通模型和直接 Tool 正文仍从消息事实投影，不为嵌套卡片创造独立模型消息。旧 Web 会话实现曾满足该契约，修复边界及同 Turn 普通大结果读取限制见 [嵌套结果冷投影修复](../bugfix/web-nested-tool-history-projection.md)；Host迁移后曾遗漏这条投影；产品修复已合入Case分支并取得确定性验证，09-28两项live已恢复取样；稳定资格与已修产品状态分别记录。

新增或实质修改 Case 后，至少在同一代码树和固定模型参数下连续运行 live 五次、deterministic 批次三次；最终联合两路均为五次。任一次失败都保留为失败样本并进入上述归因流程，不能只保留最后一次成功。当前每组最多选择 5 个 Case，每次完整实验对仍开放的每项执行 live 5 轮、deterministic 批次 3 轮、单 worker、零 retry；某项在任意一次完整实验达到对应资格 后立即记为稳定并退出本组后续实验，下一次只重跑尚未稳定的项。同一组最多经过 3 次这样的完整实验。每次之间必须依据已完成的归因采用不同且有证据的修正，并重新做静态评审和聚焦测试；达到 3 次上限仍未取得一次对应资格 的项标为 bad case，记录并进入下一组，后续补丁另冻结复验。达到规定次数全通过只是进入日常使用的初步条件；后续仍应累计通过率、失败类型和耗时分布。若反复失败来自非核心任务难度或模型路径不稳定，应拆小或更换 Case，而不是降低核心组件和结果真值要求。

分支及提交见[总体方案](harness-evaluation.md#4-分支与交付方式)，失败处置见[归因指南](failure-attribution.md)，批次上限见[设计准则](case-design.md#5-什么叫稳定什么叫全量通过)。Case 开发不修改 Kernel 或存储层；新增实现保持每 Case 独立，只保留流程实际需要的共享能力。阶段实验和覆盖状态写入 Case 台账，不复制到本文。

## 9. Case 接入与领域审计

注册集合和每项 Case 的运行状态统一见 [Case 台账](../../test/e2e/cases/README.md)。执行注册由 `evaluation-cases.ts`、`case-drivers.ts` 共同维护；本文不复制清单、稳定数量、实验耗时或 Bug 完成状态。

接入新 Case 时沿用以下实现边界：

先核对目标机制的 Mode 声明、实际代码触发条件与 Host 装配，再选择对应审计通道。`live` 执行正常用户任务，`deterministic` 注入难稳定复现的故障以验证真实 Harness 的兜底；两者的用户动作均仅从 Web UI 发起，故障剧本和后台审计不进入用户消息。

| 目标机制 | 环境与审计方式 |
|---|---|
| 文件、notebook、任务和项目资料 | 准备小夹具，按结构或文件字节核对独立真值，并绑定模型请求、Tool 生命周期与页面详情；多次合法编辑逐次重放前后源码，最终测试必须在最后修改后成功，不能固定修复只用一次 Edit |
| 根项目指令更新 | 夹具只预置初版规范，运行中变更通过 Web UI 的用户任务完成；按完整 current 内容、digest 和 appliedEffectId 关联真实请求，change 绑定变更后的首个 context epoch，不能把第三轮或历史旧值误当成固定边界 |
| 本机相对日期 | 使用真实时钟和实际 IANA 时区；selected 完整时间效果、临时 before_messages user 块与实际模型请求绑定，日期真值按公历年月日计算；页面只解析直属回答正文，不混入思考或控件，不用固定日期或假时钟制造正常覆盖 |
| 多选澄清 | 等待态通过 button role=checkbox 选择，单问题答案按选择顺序用顿号连接；回答绑定原 requestId 和新因果 Turn。完成历史为不可重复提交的 receipt，展开详情核对 li.selected；问答 Tool 卡显示“已回答”，成功状态及参数、结果另行核对。JSON 按严格语义及重复键判定，参数、结果与实际文件仍逐字绑定 |
| 自动/手动压缩和长结果外置 | 由 Contract 声明专属窗口或准备长结果，核对 Policy 提案、模型服务调用、消息替换或外置事实，不能只看最终召回答案 |
| MCP 与联网 | 由夹具拥有协议/Provider 请求记录，审计真实实现收到的参数、返回结果、筛选与模型消费；模型仍经真实 Provider 执行正常任务 |
| 后台进程与运行中输入 | 使用受控就绪条件和进程组证据，页面操作发生在真实派发之后，核对取消或排队窗口，不依赖固定睡眠猜测时序。当前 Monitor Case 由 Driver 提供临时本地 WebSocket 业务事件地址，必须唯一启动一次 Monitor，禁止 Bash 和 TaskStop，并至少通过一次 TaskOutput 取得该任务状态；允许对同一 Monitor 合理重复只读查询。唯一任务的日志、逐行诊断、执行更新服务、身份和最终消费独立闭合，且必须取得 completed、完整三帧和精确字节数。WebSocket 任务不得伪造进程 PID、signal 或 exit_code；全部实际卡片、详情和刷新仍核验。用户题面只要求持续跟进事件流，不出现 Tool 名或内部任务字段，也不承诺聊天页面运行中逐行实时展示 |
| 子 Agent | 按父子 Session、Turn、调用与通知标识关联，分别验证上下文、执行状态、结果回传和根任务续跑。已完成协作者续聊由两次 Web 用户任务驱动：首阶段完整取证后才继续，沿用同一子身份及绑定，第二子实际请求保留首任务/读取/报告历史，新结算与通知归因本次发送；前台/后台首建及合理重复读取均允许，不固定根 Turn 总数。同一 Web Host 的运行时重建不等于进程重启冷恢复 |
| PTC | 核对父 `RunCode` 与嵌套 Tool 调用、作用域及结果回传，不能用程序返回值替代真实嵌套调用证据。当前非空文件处理 Driver 是单阶段：页面只提交一次自然用户任务，在同一普通 Turn 内完整读取源数组并唯一创建派生文件；审计要求模型写入决策实际消费源数据，并用变化输入重放固定证据通道或同一写入程序，证明输出随源数据改变。逐卡核对父/子调用，嵌套结果不伪装成独立模型 Tool 消息或派发；旧两阶段说明只解释历史样本，不再描述当前 Driver。 |

`EvaluationCaseDriver.webProcessNodeImports` 只允许加载仓库内的 ESM 模块，并仅注入当前隔离 Web Host。路径会经 `realpath` 检查，拒绝绝对路径、仓库外路径及重复模块；preload 在 Web CLI 解析前执行，因此需要状态审计时必须从与 `--state-dir` 相同的 `LONGCAT_STATE_DIR` 取得当前 Case 状态根。受控 Provider 不得替换真实模型调用或污染其他 Case；架构合并后须按当前生产 adapter 的实际结构化请求重新核对夹具。JSON 请求按对象语义比较，模型可见结果按当前生产 renderer 的业务内容核对，不能预设所有 Tool renderer 都输出 JSON，也不能因 Markdown 排版变化放弃结果值、数量、顺序、域名过滤和真实消费门槛。

确定性崩溃窗口可用测试专用preload在真实方法提交前后挂起，再由Driver终止隔离Host。包装器必须调用原实现、保留原结果，不能直接写业务数据、伪造事件、改变恢复规则或把未知结果改为成功。Driver须在崩溃前独立读取SQLite和文件，证明实际命中声明窗口；重启使用同一源码、配置和数据库。标记只控制一次故障，不进入模型题面。当前实现位于`deterministic-recovery-checkpoint.mjs`，不修改Kernel或存储源码；其结果与其他故障一样逐项归因。

同值设置的次数以当前领域实现为依据：Projects 仅允许同路径、同正文且不展示的 project_write；ReportFindings 每次仍是一项相同完整 finding；NotebookEdit 首次完成 original→expected，后续只能同单元 expected→expected，逐次核对 old_source 和前后完整结构。每个实际调用的权限、raw/durable 结果、独占调度顺序、实际消费者和页面详情都保留，不能用最终文件正确掩盖中间错值。Glob 至少一次在工作区根完整发现，额外子目录查询按各自范围核验精确子集或空集，累计完整匹配集合；安全复核不增加机制覆盖计数。

手动压缩首轮使用一份结算平台灰度发布交接卡和监控附件，避免重复转述关键事实；摘要须独立保留“灰度负责人：林澈”和“异常回滚版本：2026.09.12-rc3”，selected、replace、净缩减、命令统计和实际canonical消费均须闭合。两项共享审计接受独立行、句中或行内代码引用中的明确字段，允许完整直接值后附完整括号说明；每处“字段名：值”都须完整、正确且无冲突，值后须有空白、标点、换行或文本结束等明确边界，不能只匹配正确版本号的前缀。不增加通用姓名或自然语言推断。题面仅对最终回答规定两行，不强制摘要排版。合法手动替换范围可只含长资料，也可连同首轮确认；按实际范围验证，不把保留的首答当作摘要证据。自动的摘要独占门槛检查完整实际消息，包括reasoning。命令completed仅说明产生了替换，不能代替净缩减或完整事实检查；已修复的净收益保护见[HARNESS-006](../bugfix/compaction-net-gain.md)。

若首轮确认仍在实际替换范围外，则其完整正文和 reasoning 从原模型事件、耐久消息及后续 canonical 请求逐字段核对；若已被合法替换，则后续消息面不得重新出现该确认。页面按完整 ReactMarkdown/GFM 渲染结果建立对应，并核验刷新全文。当前两项题面明确规定交接字段，业务值直接按字段核对，不额外推断同义句、历史或否定含义；来源与实际消费另行验证。

子任务停止题面与审计统一区分准备和业务执行：根聊天仅在委派前做必要的只读路径、文件及 Node 检查，委派后只查询子任务状态、提交网页选择并取消同一观察员。根聊天不能代跑观察命令或用 shell 停止进程，准备结果须独立复核，不能仅凭 Tool 名称判断只读。最终两个状态字段须唯一且精确，可附简短确认说明；真实子任务运行、取消传播、进程退出、耐久结果及刷新仍逐项验证。 提问参数校验失败的候选只有证明零派发、无交互副作用、错误耐久保存并被后续模型消费、同一轮次恢复到唯一真实问题，才不计入真实提问次数；原候选仍参与全量调用/结果核对。不得笼统过滤失败调用或允许多个真实表单。

后台合并的子Read仅允许同一指定文件相对路径触发的明确TOOL_CONTROL_FAILED合成拒绝：原始/耐久拒绝身份、完整内容及后继实际消费须一致，且没有permission、dispatch或该调用的服务交换。拒绝不计成功Read，最终实际子请求仍须收到成功完整码来源和全部读取结果；其他错误不豁免。详情逐步骤遍历全部实际Read，按顺序核对成功/拒绝状态及完整参数、结果，刷新重复全部检查，不在找到首个正确Read后提前结束。

该审计异步取得第一方文件包的实际 Read.output.render，只渲染已独立核验的固定源码切片，不执行额外 Tool I/O；再用生产 modelToolContent 投影核对完整耐久 Tool 消息和实际请求。拒绝正文必须是精确合法文本块，不能用文本 flatten 过滤图片或未知字段。Tool 来源绑定真实结果 event_id，Assistant 来源绑定 outcomeId 并核对 reasoning 与完整消息；raw/result 的 actionPlanId、ordinal 分别绑定真实调用及 canonical action 槽位，不能以两份共同错绑的结果互相证明。

运行中投递Case的初始子报告允许正常前置说明，全部baseline-code关系仍须正确且最后独立字段正确；后续child/root纯两行、Bash真实来源、投递窗口、身份和唯一通知不变。PTC正式回答使用顶层直属Markdown，活动内全部非空过程正文由真实模型/耐久来源完整绑定ReactMarkdown/GFM渲染、数量及阶段前缀，刷新完整复核；二者不能互相替代。

拥有即将随清理消失的日志或进程证据的 Driver 可以实现 `attachArtifactsBeforeCleanup`。总 spec 在关闭进程和删除隔离目录之前调用它；附件失败仍继续全部清理，并保留附件错误与清理错误。共享能力仅保留实际 Case 需要的接口，不增加单调用包装或重复辅助自检。

所有样本（成功与失败）另归档 `trajectory.jsonl.gz`：测试进程停止后，从原 SQLite 只读导出完整事件、轮次与消息行，解析并校验外置事件正文，保留各表顺序、模型请求计划、绑定及 Policy/Tool 因果事实。首行记录样本身份、清理起点和进程停止状态，末行记录完整导出计数；包含清理事件，不能将它们误认作用户动作。已知凭据脱敏，原摘要是脱敏前的校验值。它是派生测试附件，不是新运行事实库，也不等于 Provider 原始 HTTP；G2 结构分析须结合传输编码代码。归档失败阻断样本并保留原隔离目录，不静默丢弃证据。当前周入口已接入 G2 结构检查与只读裁判，结果独立呈现，不改变 G1 原判分，见 [G2 手册](../../scripts/evaluation/g2/README.md)。

完整归档只保证导出了已有事实，不保证每类事实都有完整请求。主模型 canonical 计划含 messages/tools；通用副模型服务目前只投影 purpose 等摘要，缺少完整 messages。G2 应分别标注规范、代码和动态证据，不能把这类缺口算作已覆盖；这些副请求的补取证仍需另行设计。

公共审计增加绑定要求时，原有审计单测的夹具必须同步提供当前 Mode 的完整激活绑定，避免在目标断言之前被不完整夹具拦截。保留原正反断言，不为夹具缺失增加生产豁免；规则控制、类型检查与项目自动测试通过后才进入模型采样。

公共事实加载先校验每份 canonical `action.plan.committed` 的 `actions` 必须是数组；合法空计划保留 `actions:[]`，只有带 `traceEventId` 的 trace 包络可不含该字段。后续按非空动作筛选不能静默吞掉损坏的 canonical 计划。进程测试夹具的就绪 JSON 完整写入临时文件后再原子重命名发布，避免读取异步写入的空文件；不改生产取消语义或退出断言。

该公共形状校验只验证已存在的 canonical 事件，不独自证明完整执行事实。确定性基础自检另核对其固定正常零 Tool 主模型 stop、唯一动作 trace 与 canonical 空计划的 planId/count/时序及 completed 终态，拒绝缺失、重复或冒充 trace 的计划；不把这个确定性轨迹计数套到真实模型 Case。

阶段固定版本采样在每个进程调用前后核对源码、服务端 dist、实际前端 src/ui/web-ui/dist 及本轮外部取证/报告脚本的哈希，不在采样中修改。取证是停止进程后的逐文件字节副本，不是跨库原子快照；停机失败不能声称取得共同闭合快照。通路摘要的模型身份以实际附件为准，确定性自检不能误填真实 Provider 身份，各样本随机回环端口独立保留。

协作者续聊、可继续子任务列表与历史分叉不固定页面分组或顶层回答数等于用户输入数：后台委派可能合法产生根任务过程报告与通知后的业务报告。专属审计逐根 Turn 将全部 model.completed（包括空末条）与耐久 Assistant 的来源、完整正文和 append 位置逐项闭合；completed Turn 的页面报告来自该 Turn 最新原始非空正文，空末条可以提升先前过程正文，无任何正文则不产生报告。waiting 不产生顶层完成报告。页面按来源完整核对报告数量、顺序及 Markdown 渲染正文，当前业务报告必须唯一且在最后，普通用户消息精确核对；工具组按实际用户来源定位，不使用固定 nth。刷新后完整可见报告数组必须不变。允许过程正文不豁免错误工具领域、提前发送、额外子 Turn、重复结算或通知。

Skill 任务快照保留真实加载规范、观察空清单、按规范创建三项任务及最终真值。初始 TaskList 可以先于 Skill 或与其并行，但每个创建决策的精确实际请求都必须完整消费二者，不能以任意先前请求代替当前消费者。TaskUpdate 允许合理重复、无变化字段和合法过渡状态，但逐调用从前一状态重放；目标任务必须更新到规定终态，第三项不能离开 pending，删除及无关字段仍禁止。所有带真实 taskId 的决策须已消费对应创建结果；第三次创建可以与更新前两项已知编号同批，但三项创建必须实际完整结算后才能更新。最终 Update 和 List 可由同一模型批次提出，但仅在 Update 位于前方、解析动作顺序一致、独占组串行执行且更新结果先于 List 实际开始时合法；不能把未知编号的 Create→Update 或倒序/并行变更当作同批豁免。页面与审计复用最终数量语义，重复同值与等号空白可接受，缺项或冲突仍失败。

批准文件的 Write→Read 可在同批提出，但必须具有同一模型响应与动作计划、真实 ordinal、唯一独占写组先于只读组及写入耐久结果先于读取开始的证据；跨轮复核仍要求实际请求消费写入结果。MCP 与受管理后台报告核对所有目标字段的出现，拒绝正确结果行之外的冲突或重复字段；可选后台脚本 Read 必须在启动前结算，启动后只允许用户指定的状态与停止操作。工作树过程正文可引用最终标记，最终成功仍绑定正常末次模型、真实 Exit 结果消费和完成事件。

澄清建文件逐 callId 将模型 Tool 决定、canonical action/ordinal、权限 execution、dispatch、raw/durable 及实际后续消费闭合。提问结果由因果续聊的实际请求消费，写入及其他结果不能只凭耐久存储推定模型已看到；最终实际请求必须完整收到唯一 Write 结果。已发生合法 result projection 时核对真实 selected effect 的身份、调用、Policy 点和完整投影正文，无投影仍要求 raw/durable 正文相同。

PTC 计数与文件处理中，不可见工具的合成拒绝不是实际 I/O 失败，只在专属审计完整证明 TOOL_NOT_MODEL_VISIBLE、selected/applied 拒绝、零可执行动作/权限/派发/服务、唯一耐久拒绝消息及后续同 Turn 实际请求完整消费时作为允许轨迹记录，不新增覆盖。真实核心调用、数据来源、用户确认和唯一副作用仍由完整 Case 硬验。若确有同 Turn、同目标的嵌套调用恢复，记录真实调用身份；若模型凭先前已消费结果合法结束工作流，记录已消费拒绝并完成任务，不伪报恢复调用。不能为恢复一个被挡住的错误候选，要求实际执行用户禁止的操作或重复只读复核。未知拒绝、实际执行、重复副作用、违禁 Bash 或错误数据链仍失败；这不是全局忽略 isError。

两个PTC Case与Mode的RunCode及嵌套Tool服务兼容。HARNESS-030曾因Host迁移遗漏耐久嵌套结果造成刷新后卡片回退运行中；已在单独授权下修复并合入Case分支，确定性验证通过，09-28两项live也已恢复执行。本批残留断言/模型问题见Case台账，不再以030排除。刷新前后状态和精确详情仍是硬门槛，不因另一通路通过提升live资格。

内部捕获后失败开放的 Policy 不一定产生失败事件，不能以 event_log 没有失败推定运行正常。公共 `finishAudit` 与自行结算的停止/打断审计只读核对所覆盖根/子 Session 的私态和真实交换；所有 binding 的组件集合、来源、显式 enabled、shadow 和 failureMode 必须与当前 Mode 声明一致。对于当前 Standard，契约账本的正确语义是“保留绑定但 `enabled=false`”，所以模型服务调用、私有状态和结果投影都必须为零；不能沿用旧启用版本的 ready ledger/review 门槛。对于确实启用该组件的其他 Mode 或历史冻结树，契约错误仍须关联同 Turn/Session binding、组件、显式激活及原始副模型响应；归属或激活不明、真实 artifact I/O 错误仍阻断。非目标模型的提取或复核输出错误保存到成功审计的 `policyDiagnostics`，不统一变成 Tool 核心 Case 的失败，也不计该副模型的健康覆盖。实际发生的结果投影仍须精确核对；不得为了绕开诊断临时改变 Mode 配置。诊断不证明全部 Policy 健康，不排除未持久化错误或语义误报。

非目标契约提取遇到 HTTP 429 时，`service.call.failed` 是调用的真实结束记录，不能当成缺失结果，也不能伪造 `completed` 响应。共享审计仅在调用方明确提供 Case、数据库和 Session 范围时处理这种例外：按同 Session/Turn、serviceCallId/evaluationId、请求哈希、Policy 点、序号与状态修订唯一配对开始和失败，核对真实绑定及启用状态；确认同轮私态保存原始错误、后续 canonical 请求与状态提交存在，而且主模型实际完成该请求，期间失败组件没有产生选中效果。满足这些条件的非目标契约提取 429 进入 `policyDiagnostics`，保留 `outcome=failed`、failureSeq 和原始错误；不计辅助模型健康覆盖，不叫重试成功。后续新输入触发的新提取另算一次调用，不能填补旧请求。

此例外目前只覆盖已核对实现的契约提取 429，不扩展到其他服务或复核调用的传输错误。缺失/重复终态、跨轮借用、伪造 ready、无实际继续执行、真实 artifact I/O 错误、核心策略目标失败，以及主模型和工具的未恢复失败仍阻断。业务审计、页面和刷新必须继续全部通过，辅助诊断本身不能证明 Case PASS。产物校验器同样区分失败调用与成功响应，不要求失败调用提供不存在的正文或 finishReason。

Completion verifier 的内部 catch 与合法 abstain 私态相同，另只读核对已经发生的模型服务交换：按同 Session/Turn、serviceCallId/evaluationId、Policy point、purpose、请求 hash/ordinal/revision 和真实 binding 唯一关联请求与结果，确认 State 接口、当前协议版本和模型服务 grant。归属、授权或原始响应缺失始终失败；非目标模型的非 stop、JSON 或 schema 错误，只有完整证明当前生产语义的合法 State 失败开放及其后续因果路径时，才作为根据原响应推导的诊断，不能允许未知继续路径，也不能伪称为已持久化的 Policy 诊断。有效复核为核心目标时仍需有效结果。三个合法 verdict、生产解析器接受的排版/包装/额外字段与空字符串均允许，不强求固定复核次数，不干扰主模型 length 续写或正常用户取消。新版作用域必须冻结复测，旧全局健康口径的原始成绩不回写。

在组件实际启用的冻结树或 Mode 中，契约私态已有非空组件必须是对象；status存在时仅允许ready/error，ready必须有对象ledger和数组artifacts，error允许无ledger。reviews存在时必须为对象数组，逐项检查生产五种状态、filePath及错误类型；reviewedPaths存在时必须为字符串数组，不固定合法复核次数。缺省/null仅在同Session/Turn的提取服务完成后还有后继canonical context.plan.committed时拒绝，并要求此时status已初始化；该事件与assemble私态更新同次提交，trace包络、异Turn提交或Turn.completed单独不证明初始化，合法未初始化/禁用/提交前取消仍允许。当前 Standard 的禁用组件必须保持无私态；不能用本段启用态规则允许它初始化。形状校验不复制副模型解析器，不能代替原始交换、合法失败开放及真实I/O的完整归因；未知状态、损坏集合和只读任务中的artifact review仍拒绝。

启用态契约输出归因直接复用 `src/extensions/verification/contract-ledger-reminder-policy.ts` 的 `parseContractLedgerModelResponse` 纯函数，只包模型文本解析的catch，交换归属、激活与私态完整性仍在catch外；finishReason及无content检查按completeJson保持一致。该函数不导出稳定 API 或 `src/index.ts`，不增加服务。引用artifact JSON与末尾唯一结果可区分，但重复/冲突结果、重复键、未闭合/损坏目标块、顶层数组和矛盾verdict/discrepancies仍报错。旧冻结的原响应与私态由旧解析器解释，新函数对旧响应仅是独立反事实控制，不追认旧成绩或混用解析器；当前 Standard 禁用态不会进入这条解析路径，Completion verifier保留自身领域协议。

已提交初始化还须按同evaluation的末次提取交换核对失败状态及原错误，不允许真实末次格式错误被伪ready抹掉诊断；首次length后末次重试成功仍合法。复用现有原响应错误识别，不要求全部提取响应有效，也不把后置artifact复核全部私态持久化完整性当作已覆盖。

targeted-fix 与受管理后台进程的目标真值分别由文件、独立测试和受管理进程终态判定，不把所有 Mode 都已禁用的 completion_verification 声明为必需证据，也不据此声称 reviewer 能力获得覆盖。非目标副模型的明确输出错误仍完整留在诊断；声明目标有效复核的其他 Case 及确定性通路继续保持严格协议门槛。后置产物校验只验证诊断结构和原始交换并转存到汇总，不另用离线规则重判模型答案。

根项目指令、日期和多选澄清流程另有目标终态审计，并在清理前把相关事件和目标 Policy 状态保存为 `{ events, policyStates }`（可带业务文件）；旧事件数组附件不具有终态状态证据。共享失败诊断在每个 Turn 元数据旁保存 `policyState`，仍由总 spec 对已知凭据值脱敏；私态可能含固定任务和产物内容，不能把诊断当作仅有无内容计数的日志。普通 host.question 原始事实省略 kind 时按现有协议解释为 user_input；审批仍须明确区分，权限 target 的可选描述不能替代执行身份和分类字段。

确定性故障 Case 使用匹配需求的模型剧本、受控故障/重启生命周期及预期错误断言。故障必须由环境注入，页面仍提交自然用户任务；只允许已声明且被逐项核对的预期错误，不能通过全局忽略错误把运行改成通过。基础自检没有这种失败豁免。

确定性故障剧本遵循以下边界，当前注册与证据见 [Case 台账](../../test/e2e/cases/README.md)：

- 剧本通过测试进程参数选择，每个样本隔离状态；先校验实际请求和阶段，再返回响应。未知请求、替身校验失败与计划内注入故障分开记录，前两者即使被生产重试恢复也不能通过测试。
- 含失败请求的审计按每个请求计划关联成功或失败结果，保留Turn、attempt、请求身份及重试决策。不直接沿用`mainModelRounds`中“计划数等于成功数”的正常路径前提，也不允许孤立请求被过滤掉。
- 预期错误只在对应Case内逐项验收；注入的500、429等不进入外部网络作废补样。普通live及基础自检的错误门槛保持不变，Runner、UI、Tool和存储错误不会因剧本含故障而获得豁免。
- 替身不得预写业务结果或伪造Tool事实；后继响应须校验真实前文/Tool结果已进入请求。Driver可控制外部故障或响应释放时机，业务输入仍只能通过页面，审计只读。
- 硬限制Case须证明普通权限规则已允许、实际执行包装仍拒绝，不能把普通审批拒绝冒充硬限制生效。并发文件修改只作为外部协作者故障注入，不能用夹具写出用户要求的目标结果。
- 根停止除了子请求关闭、后代终态，还需检查是否意外启动内部通知轮。HARNESS-042曾复现后台等待时停止后重新调用模型，现已在独立产品分支修复并验证；前台停止通过不能代替此边界。后台等待用耐久turn.waiting确认，不能从页面会话仍显示running推断策略未等待。
- Tool参数解析/Schema失败必须与实际执行失败分开审计：前者无dispatch，后者必须有真实dispatch及对应raw/final结果。JSON参数比较语义值，不固定键顺序；保留失败码、原始输出、耐久消息、后继请求消费和刷新卡片，不用最终一句成功替代完整因果链。

打断 Case 的全部消息闭合包含合法初始 system 消息：逐 Session 核对唯一初始 Turn、`system_message.seeded`、逻辑消息 ID、物理 seq、稳定来源、空 source_event_seq，以及按 API canonical JSON 重新计算的消息 hash；种子必须位于输入提升之后、首次模型请求之前。只有这些消息才可计入输入、模型和 Tool 的总数闭合，不能任意忽略 system 角色或来源。该检查不把测试清理生成的取消事实当作业务打断。

子任务停止审计允许产品内部已经严格证明恢复的主模型请求失败，复用 `recoveredModelRequests`，不再在最终事件检查中再次无条件拒绝。必须有同 Session/Turn、原请求哈希、递增 attempt、新 plan、真实绑定、被选中的重试提案及其耐久归因，且在配置预算内实际完成；期间不得提交失败输出或派发工具。限流退避也必须逐条对应选中效果。仅这条已证明链路的失败和退避事件记入 `recoveredModelEventSeqs`，原记录不删除。未恢复、错请求、空响应、未知错误、其他失败或错误执行中断仍拒绝；唯一观察员、真实用户决定、同一子任务取消、进程组退出、业务状态及页面刷新要求不变。这属于同一次样本里的产品恢复，不是作废或补样。

持续广播主动停止 Case 的“没有自动结束时间”按 Monitor 的实际生效期限核验，不能仅证明主动停止早于期限。仍需真实输出被消费、同一任务主动停止、源端连接关闭、唯一连接和刷新。前后完整审计均通过时，收尾事件的数量单调增加不属于业务变化；其他审计事实必须保持一致，不笼统忽略元数据或工具结果。

Goal 取消也以目标取消、原问题关闭、零业务写入、空队列及刷新为业务要求。非目标契约提取失败按上述精确辅助诊断核验保留原始证据，不要求辅助模型必须健康或重试成功；关键业务错误不豁免。延后与刷新均重新执行完整审计，只允许事件数量单调追加，其他取消与耐久事实必须一致。

## 10. 文档更新边界

文档唯一职责见[文档入口](README.md)。本文只随 Contract/Driver、证据通道、隔离环境或领域审计协议变化而更新；新增文件和注册顺序见[新增 SOP](new-playwright-case-sop.md)。具体资格与失败记录进 Case 台账。

## 11. 样本与判定边界

取样门槛统一见[设计准则](case-design.md#5-什么叫稳定什么叫全量通过)，正式入口通过 `sample-requirements.mjs` 执行相应要求；补样资格与保留原失败的方法见[归因指南](failure-attribution.md#5-网络429长尾与补样)。以下只说明专属审计不能放宽的关联。

新计划类 Driver 通过页面提供的业务回答控件操作，审计分别关联 `host.human_input.*` 与 `permission.approval.*`，同轮暂停续接、批准内容和实际业务写入均须闭合。用户编辑计划是业务内容变更，不是前端自动授权；后台事实与刷新投影均需验证。

共享只读证据审计区分原工具消息与`append_content`：每个结果仍只有一个原始消息，追加必须指向相同逻辑消息、关联真实追加事件且仅增加声明内容，并按请求时点验证实际消费。准备阶段拒绝可有`raw_result`但不能有`dispatch.started`；只有已限定的可恢复搜索参数拒绝才允许继续审计，必须另有成功搜索证明业务覆盖。不能用最终答案正确掩盖未触发的核心机制。

确认语不固定标点或措辞。分叉审计从实际已落盘的确认回答核对根历史、子历史和刷新，不从预设答案推导历史事实。FIFO 首轮允许自然业务标签，后续算术和队列顺序仍严格；取消收据的问题身份必须包含并匹配原问题真实轮次。只读发现与复核允许重复，但每个调用仍独立核对权限、归属、唯一派发、返回、耐久记录及后继消费；PTC 唯一写入和变化输入的数据依赖验证不放宽。
