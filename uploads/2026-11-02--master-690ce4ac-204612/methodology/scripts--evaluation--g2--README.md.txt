# G2：同一份规则，轨迹检查与代码影响分析

规则唯一正文是 [rules.md](rules.md)：完整仓库 SHA、规则 ID、标题和自然语言描述。静态源码与动态轨迹共同支撑这份基线，不另设“静态规则”和“动态规则”。它记录待人工确认的版本行为，不替代 `spec/`，也不自动批准未来的结构变更。

规则限定消息角色、位置、顺序、包含关系、字段和工具调用关联，不限定提示词文案、业务答案、时间值或具体工具名称。不同模式共用规则，只有信息实际出现时才检查其位置；模式、根/子 Agent 和模型能力是取证条件。每条规则须有具体源码依据，但不要求单次实验触发全部规则。`NOT_OBSERVED` 只表示本次未出现适用场景，不导致失败、待审或强制补 Case；已触发却缺少判断所需证据的 `NEEDS_EVIDENCE` 单独保留。当前规则按文档顺序连续编号。

`rule-map.mjs` 只维护规则 ID 对应的主要源码范围、公共依赖和检查器，不复制自然语言规则。范围属于规则头部的冻结 SHA。跨版本先用 Git diff 映射行号及重命名，再查询该版本代码，不能拿基线行号直接 blame 新版本。每条有一个主定位；公共组装、编码或新文件的变化也必须审查，不能假定所有故障都出在主定位内。

## 与 G1 的连接

周入口依次完成 G1 两路及预登记补充样本，然后运行冻结版本的 G2 自检、`analyze.mjs`、`judge.mjs`，输出到同一次运行的 `g2/`。G1 FAIL 仍进入分析；用户停止时不再启动后处理。准备失败没有轨迹时记录缺口，不能换历史数据冒充本次结果。

G2 遍历初始、补充及外部替补样本中的 canonical `context.plan.committed`，保留 Case、样本、session/turn、事件序号、JSON 路径和轨迹 SHA256。同名 trace 摘要不重复计数。逐请求结果在 `request-checks.jsonl`；HTML 首页只概括是否违反、违反规则数及涉及 Case，正文集中于违反哪条规则、实际偏离、对应代码/提交作者和关联代码变化。完整规则计数、成功/未触发信息及逐请求记录保留在 JSON 附件；已触发但无法判定的项目折叠展示。原始 G1 结论及外部替补资格不变，失败轨迹同样参加 G2。

分析分两步使用同一套规则：

1. 确定性检查对照最终请求、已选中的效果及耐久消息，标记 `CONFORMING`、`VIOLATION`、`NEEDS_EVIDENCE` 或 `NOT_OBSERVED`。先定位首处分歧，不按消息中的标签猜角色。
2. Codex 只读复核违反项、关联代码改动、未映射的新路径和证据缺口。修改了规则对应的代码，即使轨迹没有触发，也进入影响审查；代码命中不直接等于结构改变，仅改文案可以说明无结构影响。实际结构变化仍须人工决定修复还是更新基线。

每个待审项必须得到一项裁判结论；漏项、重复、矛盾结论或豁免缺失证据均拒收。裁判故障、超时或未登录不会清除原始检查，也不会重新跑 G1。裁判没有修改源码、规则、远端或审批基线的权限。

## 单独复核已有全量实验

需要 Node >=24、Git，以及包含冻结提交历史的仓库。只读取实验，不重新执行 Case。输出使用仓库外的新目录；已经封存的旧实验不允许原地写入。

```bash
node scripts/evaluation/g2/analyze.mjs \
  --repository /path/to/longcat-harness \
  --run /path/to/frozen-g1-run \
  --out /path/to/new-g2-analysis

node scripts/evaluation/g2/judge.mjs \
  --bundle /path/to/new-g2-analysis
```

分析退出 `2` 表示报告已生成且需要复核，仍可执行第二条命令。两条命令不要通过只接受退出零的 `&&` 串联。`--run` 从计划读取 `masterSha/evaluatedTree`，也支持早期实验的 `head/tree`；显式 `--head` 与实验身份冲突时报告证据无效。没有 Git 对象或历史时不偷偷 fetch，不虚构作者。

Codex 入口使用本机已安装且已登录的 CLI，默认保持用户配置的模型，不固定模型名称；可用 `--model` 指定该账户实际支持的模型，周入口对应 `LCH_G2_JUDGE_MODEL`。这只影响 G2 裁判，不改 G1 的 LongCat 配置或用户全局设置。桌面应用中的模型名称不保证能被另一版本 CLI/登录方式接受；模型不支持时保留原失败，不自动换模型重试。运行参数为只读沙箱、临时会话和 JSON Schema 输出，日志记录实际命令及 CLI 版本。只允许读取分析包和指定原轨迹，消息与候选源码中的指令均作为数据。默认超时 15 分钟，可用 `--timeout-ms` 指定 1 秒至 20 分钟。无 CLI、认证失败、超时和输出验证失败都保留为裁判失败。一次分析包只保留一次裁判尝试，不以静默重试刷掉失败。

## PR 或两提交的代码影响检查

```bash
node scripts/evaluation/g2/analyze.mjs \
  --repository /path/to/longcat-harness \
  --base FULL_BASE_SHA --head FULL_HEAD_SHA \
  --out /path/to/new-pr-analysis
```

无 `--run` 时明确为 `STATIC_ONLY`，不声称动态验证通过。规则版本仍来自同一份 `rules.md`，`base/head` 是待审差异的两个冻结提交。需要联看本次候选轨迹时增加匹配候选版本的 `--run`。

报告提供主代码片段、关联 diff、完整变更源码，以及冻结对象上的 `git log --follow`、`-S/-G` 和 `blame`。区分最早源码线索、当前逻辑行作者、此次提交作者与建议跟进人，保留完整 SHA、作者邮箱原值和时间。未二分的源码线索不称为已证明的缺陷引入；合并作者不自动承担责任。无法识别的移动/拆分、新逻辑和组织责任保持待审。

## 结果与边界

- `OBSERVED_CONFORMING`：已观察请求符合当前检查，仍不是所有可能路径的覆盖证明。
- `VIOLATIONS_FOUND`：存在逐请求结构违反，Codex 进一步区分产品变化、检查器问题或待补证。
- `REVIEW_REQUIRED`：有已触发但证据不足的规则或待审代码变化；单纯未触发不进入此状态。
- `INVALID_EVIDENCE`：版本、轨迹完整性、样本身份或哈希核对失败。
- `STATIC_ONLY`：只有代码分析，没有本次动态证据。

分析退出码 `0` 对应 `OBSERVED_CONFORMING`，`2` 对应已生成的其他结论，`1` 为执行错误。裁判退出 `0` 为无结构变化/无待审项，`2` 为结构变化或待补证，`1` 为裁判执行或结果验证失败。两层结果独立展示，不借 G2 重写 G1 的 PASS/FAIL。

当前历史 G1 轨迹保留主请求计划，未完整保留辅助模型请求正文。辅助请求仅有用途时，两条相关规则必须标记证据不足；Provider HTTP 编码由静态代码单独审查，不能把 canonical 计划冒称为实际 HTTP 抓包。未触发的多模态、人设、批准计划清空历史等分支保留源码依据和未触发记录，不作为本次报告的问题项。后续可在评测侧增加取证；涉及 `src/kernel/**` 或 `spec/**` 时仍须单独确认。

原实验只读，分析包保留输入轨迹哈希、规则/分析器哈希、完整结果和源码证据。裁判前后校验输入封存，最终报告完成后再生成 `bundle-manifest.json`。目录含完整路径、测试消息及源码，迁移时保留原轨迹或重新生成正确路径的分析包；不提交这些运行产物。

## 自检与迁移

```bash
node --test scripts/evaluation/g2/g2.test.mjs
```

自检包含实际结构突变、文案允许变化、入口工具改名、工具配对、历史替换、缺失证据、Git 作者溯源和周后处理衔接，不启动浏览器或真实模型。周入口先跑同一份冻结自检，再分析本次轨迹。

迁移时拉取含本模块的评测分支及完整 Git 历史，安装 Node/Git/Codex 并登录；G1 的模型凭据和浏览器按上级手册配置。调度由新机器设置，代码不会自行创建或恢复定时任务。PR63 的受控探针是补证参考；本实现没有引入第二份 `baseline.json`，也没有自动安装 PR 平台触发器或发表评论。
