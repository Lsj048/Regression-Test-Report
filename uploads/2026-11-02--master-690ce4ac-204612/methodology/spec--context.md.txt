# 上下文与模型请求

本文件是规范性文件。适用范围、术语及变更规则见[规范入口](README.md)。

<a id="ctx-01"></a>

## CTX-01 固定阶段边界

每次正常构造请求先 `assemble`（装配来源、系统片段与工具可见面），后 `fit`（消息投影与预算适配）。后者读取前者已经物化的快照；顺序链中的后续策略读取前序有效效果。`assemble` 不得持久替换或追加消息内容，`fit` 不得重新修改系统片段或工具集合；越界效果必须拒绝。能力选择只能使用已装配或按协议动态注册的获准资源，发现能力不等于获得授权。

<a id="ctx-02"></a>

## CTX-02 区分消息事实与临时投影

`messages` 是完整消息事实，`surfaceMessages` 是持久操作折叠后的可见历史，`visibleMessages` 是本次请求投影。临时记忆、时间、能力说明通过运行时上下文进入请求，不冒充真实用户输入或永久消息；指向当前输入的覆盖只修改请求投影。基础提示词首次使用或变化时作为系统消息保存；压缩摘要通过内核提交的 `replace_range` 成为持久事实，不保存第二套策略私有消息检查点。

<a id="ctx-03"></a>

## CTX-03 持久消息操作必须精确

`replace_range` 只替换当前连续范围并校验其修订；`append_content` 只向当前指定消息追加非空内容，保留逻辑消息编号、角色、调用关联和原始来源，文本分隔由贡献者提供。目标缺失、已被替换或校验值过期时必须拒绝，不猜测替代目标。内容追加只能发生在 `fit` 或 `on_model_error`；后续替换必须把追加后的修订纳入校验。原始事实永不覆写或删除。

<a id="ctx-04"></a>

## CTX-04 请求可重建、预算不虚报

最终规范化的 `ModelRequestPlan`（模型请求计划）、组成部分摘要及归因必须先于模型调用持久化；模型适配器只做可由计划和绑定重建的传输编码，认证信息不得进入事件。输入计数覆盖消息、工具、模板及请求参数；支持精确计量时标记 `exact`，否则明确标记 `estimated`，不得把启发式估算当准确值。系统、工具和上下文排序须确定；组件声明的会话或轮次稳定内容应保持相应生命周期内的稳定性，真实能力变化不得为缓存而隐藏。

<a id="ctx-05"></a>

## CTX-05 上下文修复优先于模型重试决策

模型异常先进入 `on_model_error`；仅生成不同的有效请求面才算修复成功。未修复时进入 `on_llm_error`。上下文策略不得自行重试模型，状态策略不得修改上下文；不变的修复不能造成无限重试。模型重试与策略续写均须遵守已绑定的有限预算及取消信号。
