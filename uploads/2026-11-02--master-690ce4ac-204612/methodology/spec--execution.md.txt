# 工具执行、限制与公共服务

本文件是规范性文件。适用范围、术语及变更规则见[规范入口](README.md)。

<a id="act-01"></a>

## ACT-01 工具契约只有一份

工具拥有模型可见名称、说明、参数格式、结构化结果及原生渲染，也拥有权限、超时、并发和副作用语义。宿主只装配及附加来源身份，不编译另一套模型契约。执行必须校验参数、作用域、权限、依赖和并发限制；不存在于当前作用域的工具不能通过直接调用或服务入口绕过限制。模型可见集合与执行授权必须分开：工具暂时不展示给模型，不等于撤销复合工具已获准的嵌套调用能力；嵌套调用仍须统一检查作用域、权限及执行限制。

<a id="act-02"></a>

## ACT-02 拒绝必须成为模型事实

动作策略只返回拒绝原因和模型可见说明。内核必须为每个显式拒绝生成关联原调用编号的 `denied` 结果及工具消息，不实际派发；随后进入 `after_actions`。整批拒绝也必须让模型在状态仲裁允许继续时看到拒绝并调整，不能把“没有可执行动作”直接当完成。

<a id="act-03"></a>

## ACT-03 执行限制必须实际生效

策略以 `id/version/parameters` 通用外壳贡献要求；工具登记精确版本、受支持的参数格式和执行包装器。未知协议、版本不匹配、非法参数、缺少执行器或无法准备执行时必须拒绝，不能忽略。全部限制保留并共同生效；嵌套调用继承外层限制，空列表不能清除。执行准备必须检查最终重写参数，且准备阶段不得执行目标副作用。核心不枚举领域限制类型。

<a id="act-04"></a>

## ACT-04 询问偏好不是授权

`ask_permission_by_default` 只影响默认询问；显式权限规则、宿主权限上限和不可覆盖的硬限制分别执行。用户同意、规划审批、宽松权限模式和嵌套工具都不能使硬限制失效。约束不支持时不得先弹授权请求，再把同意当成约束实现。

<a id="act-05"></a>

## ACT-05 结果沿唯一管道提交

工具执行产生结构化结果及原生内容，随后按配置顺序通过上下文策略的结果投影链，最后提交模型消息。投影之后工具不得重新扩张内容。必须区分并关联 `tool.call`（原始调用）、`tool.dispatch.started`（真正派发及最终参数）、`tool.raw_result`（策略前结果）、`tool.result`（最终结果）。未派发的拒绝不伪造派发事件；恢复中的未知副作用按 [DATA-04](persistence.md#data-04) 处理。

<a id="svc-01"></a>

## SVC-01 服务用于跨越真实核心边界

每项公共服务有名称、版本、输入输出格式、调用者类型和授权语义。包声明申请上限，模式逐组件授权，宿主权限是最终上限。扩展只能枚举和调用自己的授权服务；工具控制器不继承被控工具的授权，同名替换工具不继承原实现的能力。服务只在宿主装配时注册；扩展不能获取原始注册表或替换核心服务。普通文件、网络及领域逻辑不因常用就升级为核心服务。状态快照的直接读取遵守 BND-02、BND-05 和 POL-05，不要求为同领域读取新增服务。确实通过公共服务协作时，依赖声明仍不能代替该服务的授权。

<a id="svc-02"></a>

## SVC-02 模型调用遵循相同授权与记录

三类策略通过公共服务或等价的 `PolicyExecutionContext.llm` 使用宿主模型，不自行装配供应商。会进行外部读写的服务只授予 `recorded_external_io`（通过记录恢复外部读写）的策略。每次调用关联组件、轮次、评估点和取消信号，记录开始、完成或失败。

<a id="svc-03"></a>

## SVC-03 重放不能再次制造外部作用

恢复时按轮次、组件、扩展点、状态修订、评估作用域、服务版本、调用序号和请求摘要定位调用。已有完整结果则复用；已记录失败则保留失败；只有开始、没有可确认结果时必须明确报未决，不得盲目重新调用。不能承诺外部世界“恰好执行一次”；承诺的是不把未知结果当成未执行，并保留可诊断事实。
